Steam 版《王国保卫战：前线》（Kingdom Rush Frontiers）的**单文件修改器**：
不到 80 KB 的一个 exe，深色界面 + 12 个实时开关 + 一次性战斗操作 + 存档修改，
勾选即生效，随时可开可关，**关掉会把改过的值还原**。

> A single-file trainer for the Steam release of *Kingdom Rush Frontiers*.
> It appends a Lua hook to the game's LÖVE archive and talks to it through two
> tiny files — no DLL injection, no memory scanner, no code patching.

## 功能

### 游戏内实时功能（12 项，可随时开关）

| # | 功能 | 热键 | 说明 | 实现方式 |
|---|---|---|---|---|
| 01 | 无限金币 | `F1` | 金币锁定 999999 | 每帧顶 `store.player_gold` |
| 02 | 无限生命 | `F2` | 生命锁定 99 | 每帧顶 `store.lives` |
| 03 | 秒杀敌人 | `F3` | 持续清空地图上所有敌人 | 把敌人 `health.hp` 归零 |
| 04 | 友军无敌 | `F4` | 我方士兵与英雄免疫伤害 | 置 `health.ignore_damage = true` |
| 05 | 我方满血 | `F5` | 我方单位血量始终回满 | 每帧 `health.hp = health.hp_max` |
| 06 | 敌人脆弱 | `F6` | 敌人血量降到 10% | 改 `difficulty_enemy_hp_max_factor` |
| 07 | 敌人减速 | `F7` | 敌人移速减半 | 改 `difficulty_enemy_speed_factor` |
| 08 | 敌人定身 | `F8` | 敌人完全无法移动 | 置敌人 `motion.max_speed = 0` |
| 09 | 技能无冷却 | `F9` | 陨石雨 / 援军随时可用 | 见下方说明 |
| 10 | 分数拉满 | `F10` | 得分锁定 999999 | 每帧顶 `store.player_score` |
| 11 | 英雄经验倍率 | `F11` | 英雄经验 ×50 | 改 `hero_xp_gain_per_difficulty_mode` |
| 12 | 解锁全部防御塔 | `F12` | 解锁含未解锁的高级塔 | 置 `DEBUG_UNLOCK_ALL_TOWERS` |

**所有开关都是可逆的**：关闭时会把改过的值还原 —— 金币/生命/分数回到开启前的数值，
敌人属性回到原值，技能冷却恢复计时，`DEBUG_UNLOCK_ALL_TOWERS` 复位。

### 战斗操作（一次性，点一下立即生效）

| 按钮 | 作用 |
|---|---|
| 清空全场敌人 | 立刻秒掉地图上所有敌人 |
| 我方全体满血 | 立刻把我方士兵与英雄治疗满 |
| 技能立刻就绪 | 立刻结束陨石雨 / 援军的冷却 |
| 全部关闭 | 一次性关掉所有 12 个开关并还原 |

实现上走一个独立的指令文件：exe 写入一条指令，游戏读到后执行一次并清空该文件。

### 存档一键修改

| 按钮 | 依据 |
|---|---|
| 宝石拉满 | 宝石 → 999999 |
| 全关卡三星 | 22 关 × 5 星 = **110**，正好等于游戏内置的 `max_stars` |
| 升级树全满 | 从游戏 `upgrades.lua` 读出 31 条升级项，最高 tier = **5** |
| 英雄满级 | `hero_xp_thresholds` 最高档 **115300**（10 级），5 个技能各 3 级 |
| 道具拉满 | 炸弹 / 冰冻 → 99 |
| 一键全解锁 | 以上全部 + 解锁成就 |
| 还原最近备份 | 每次写入前自动备份成 `slot_1.lua.bak-日期时间` |

### 界面

- **深色主题**：功能行带序号徽章 / 热键胶囊 / 开关滑块，顶部渐变横幅，底部状态栏
- **热键可自定义**：点功能行右侧的胶囊，按下新键即可（Esc 取消，Backspace 恢复默认）
- **悬停即说明**：鼠标停在功能行上，状态栏显示该功能的详细说明
- **窗口置顶** / **按键音效** 两个选项
- DPI 感知，高分屏不发虚

## 快速开始

### 方式一：下载 Release（推荐）

1. 到本仓库的 **Releases** 页面下载 `KrTrainer.exe`；
2. 双击运行 → 点右上角 **「激活修改器」**（自动备份原版并注入，约 1~2 秒）；
3. 正常启动游戏，点开关或按 `F1`~`F12`。

### 方式二：自己编译

需要 Windows 自带的 .NET Framework 4.x（Win10/11 默认已装），**不需要安装任何 SDK**：

```bat
git clone https://github.com/<你的用户名>/kingdom-rush-frontiers-trainer.git
cd kingdom-rush-frontiers-trainer\src
build.bat
```

产物是 `src\KrTrainer.exe`。改过 `payload.lua` 之后建议先跑一次语法自检：

```bat
python tools\check_payload.py
```

### 命令行（可选）

```bat
KrTrainer.exe --install        安装到游戏（等价于点「激活修改器」）
KrTrainer.exe --uninstall      还原原版游戏
KrTrainer.exe --status         查看游戏目录 / 安装状态 / 进程状态 / 存档目录
KrTrainer.exe --selftest-save  自检存档读写是否与游戏格式逐字节一致
```

## 它是怎么工作的

```
KrTrainer.exe ──写──▶ %APPDATA%\krft_trainer\control.txt   （12 个开关，每 0.5 秒读）
              ──写──▶ %APPDATA%\krft_trainer\command.txt   （一次性指令，读完即清空）
                                    │
                                    ▼
                      游戏内的注入脚本 ──▶ 改写战场状态
```

**exe 是开关的唯一来源**，所以界面、热键、游戏里的效果三者永远一致。

游戏内的注入脚本**不改任何游戏逻辑代码**，只做两件事：

1. 用 Lua 的 `debug` 调用钩子被动观察函数参数，定位战场状态表 `store`；
2. 每帧把对应字段顶回去 / 改掉。

**关键细节**：每打一关游戏都会生成一张新的 `store` 表，所以捕获是**可累积**的
（用弱键表收集，旧表被回收后自动消失），换关后功能依然生效。

### 为什么能改一个 LÖVE 游戏

游戏本体是 **LÖVE 0.10 + LuaJIT 2.0.4** 打的包，源码全部是 LuaJIT 字节码（魔数 `\x1bLJ`）：
exe 是 90 KB 的 PE 存根 + 追加的 zip。修改器做的事情是：

1. 解析归档，取出原始 `main.lua` 字节码存成 `main_orig.lua`；
2. 放一份自己的 Lua 源码 `main.lua` 进去 —— 它先执行原版入口，再装钩子；
3. 把归档重新打包、拼回 90 KB 前缀 → 覆盖游戏 exe（原版备份为 `.dsh-backup`）。

重打包时未修改的条目是**原样搬运压缩字节**的，所以 450 MB 的归档 1~2 秒就能重建完。

### 技能无冷却是怎么做的

技能按钮的状态机是 `ready / cooldown / highlighted`，冷却时间由 `cooldown_view` 显示。
游戏里内置了一个调试信号 `debug-ready-user-powers`（对应 `game_gui` 的
`debug_ready_user_powers_handler`），能让技能立刻结束冷却。

**但不能周期性发这个信号** —— 每发一次游戏就会播一次"技能就绪"提示音，非常吵。
所以改成事件驱动：只在「开关刚打开」和「玩家刚用完技能（`power-used` 信号）」两个时机各发一次。
英雄技能则直接清 `timed_attacks` 组件里的冷却类字段（关闭时还原）。

细节和踩坑记录见 [`docs/REVERSE-ENGINEERING.md`](docs/REVERSE-ENGINEERING.md)。

## 目录结构

```
├── src/                         修改器本体（C#，单文件 exe）
│   ├── KrTrainer.cs             全部逻辑：界面 / 热键 / 归档重打包 / 存档读写
│   ├── payload.lua              注入游戏内的 Lua 脚本（编译时作为资源内嵌）
│   ├── app.manifest             DPI 感知声明（否则高分屏会发虚）
│   └── build.bat                一键编译（调用系统自带 csc.exe）
├── tools/                       逆向工具链（Python 3）
│   ├── _paths.py                统一路径解析（自动定位 Steam 安装目录）
│   ├── extract_love.py          从 LÖVE 融合 exe 里提取归档
│   ├── repack.py                重建 LÖVE 融合 exe（替换 / 新增条目）
│   ├── extract_strings.py       从 LuaJIT 字节码里提取字符串常量
│   ├── lua_host.py              ctypes 加载游戏自带 lua51.dll，在进程内跑 Lua
│   ├── loadmod.py               在 LuaJIT 里加载游戏自己的字节码模块并内省
│   ├── probe_components.py      用真实 entity_db 加载组件模块，还原实体结构
│   ├── check_payload.py         用游戏自带的 LuaJIT 给 payload.lua 做语法自检
│   ├── q.py                     在字符串常量表里做带文件归属的检索
│   ├── build_injected.py        把指定 Lua 作为 main.lua 打进游戏副本，用于实验
│   └── test_savegame.py         存档读写往返测试
├── docs/                        逆向过程、踩坑记录、发布教程
├── extracted/                   ← 从游戏提取的字节码（.gitignore，需自行生成）
└── disasm/                      ← 分析产物（.gitignore，需自行生成）
```

分析用的两个目录不在仓库里（里面是游戏版权内容）。想自己复现：

```bat
python tools\extract_love.py --all     # 提取归档到 extracted/
python tools\extract_strings.py        # 生成 disasm/ALL_STRINGS.txt
```

## 还原

- 游戏本体：界面里点 **「卸载并还原游戏」**。
- 存档：点 **「还原最近备份」**。
- 单个开关改过的值：把开关关掉即可（会自动还原）。

## 注意事项

- 改存档前**请完全退出游戏**，否则游戏退出时会把内存里的旧存档写回去、覆盖你的修改。
- 如果发现改完的存档被还原，多半是 Steam 云同步在启动时用云端版本覆盖了本地 —— 先完全退出游戏再改，改完直接从游戏目录启动一次让它上传即可。
- 游戏是单实例的：重复启动时新进程会自行退出，已有实例保留。
- 杀毒软件可能对"重打包游戏 exe"报毒，属误报；不放心的话可以只用存档修改功能。
